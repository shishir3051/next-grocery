FreshBasket UI Redesign

The store looked like several apps stitched together. Checkout had its own red brand, product rows stayed blank until a scroll animation fired, the cart drawer slid under the header, and most pages had no navigation. This pass introduces one design system and applies it to the storefront, checkout, account, content and admin screens, without changing behaviour.

Scope: about 55 page and component files, in two rounds Captured: live app, seeded preview database, headless Edge Viewports: 1440 × 900 desktop, 390 × 844 phone

What was wrong

  • Broken

    Blank catalog. Product cards started at opacity: 0 with a 3D rotate and only appeared via whileInView (once: false). Anything not yet animated showed as empty space, including in screenshots, link previews and for slow devices.

  • Broken

    Cart drawer under the header. The drawer (z-40) sat below the fixed header (z-50), hiding its title on phones. Its shadow also bled onto the right edge of every page while closed.

  • Broken

    Checkout summary hidden. A fixed bottom bar covered the order summary and wallet line; the disabled Confirm button was a faded pink that read as an error.

  • Inconsistent

    Two brands. Teal storefront, red checkout (43 hard-coded #CC0000), a red delivery badge in the header, purple and orange tool buttons, and an ignored Tailwind v3 config naming a third palette.

  • Inconsistent

    No shared navigation. The header only existed on the home page; news, offers, orders, wishlist and profile each had their own back-arrow bar or nothing.

  • Accessibility

    Unlabelled controls and low contrast. Zero aria-labels, borderless grey inputs, 8–10 px uppercase labels, and grey-400 body text.

The design system

Tokens live in src/app/globals.css as Tailwind v4 @theme colours, so they are real classes (bg-brand-600, text-danger-600). The written rules are in docs/design/DESIGN_SYSTEM.md, and src/components/ui/Button.tsx is the shared button.

Colour roles (palette v2)

brand: actions, links, prices (600 = 5.5:1 on white)
success (leaf): freshness, organic, confirmations
accent (tangerine): deals, savings, low stock
neutrals (sage): text, borders, canvas
danger: errors and destructive actions only

Type scale (Inter in the app)

Page title 30 Section title 20 Card title 14 semibold Body 14 in slate-700 Meta 12 in slate-500, the minimum

Shape and focus

81216pill

Inputs and chips 8, buttons and cards 12, panels and drawers 16. A global :focus-visible ring, 40 px minimum touch targets, and reduced-motion support.

Engineering notes

Architecture

  • One global header: SiteHeader in the root layout renders Navbar on every storefront, content and account page. On non-home pages search submits to /?q=….
  • Navbar works in two modes: controlled by HomeClient on /, standalone everywhere else.
  • Shared primitives: Button (4 variants, 3 sizes, link mode) and cn() using the already-installed clsx and tailwind-merge.
  • Deleted the dead tailwind.config.ts; tokens are in CSS where Tailwind v4 reads them.
  • Admin screens share one style module, components/admin/adminStyles.ts (panels, tables, fields, badges, icon buttons), instead of per-page copies.
  • Hero banners: admins used to type Tailwind class names that Tailwind v4 never generates, so some banners rendered blank. lib/heroThemes.ts now provides 7 presets written as literal classes, picked from swatch cards, with a Custom option that keeps existing values.

How it was verified

  • Eleven areas redesigned in parallel on separate files, each re-read by an independent reviewer that diffed against the original for behaviour changes. Reviewers found and fixed real issues: the cart drawer stopped animating under Tailwind v4's translate property, drag-and-drop image upload was lost in two editors, focus dropped to the page when the chat closed, and a mobile action bar covered the news form.
  • tsc --noEmit clean; ESLint down from 304 to 191 problems with no new errors.
  • Ran the app and checked header search from another page, the admin role gate, the hero edit dialog (prefill, custom theme, Escape to close) and the console (no runtime errors).

Known gaps

  • Admin dialogs close with Escape but don't trap focus or return it to the button that opened them; a shared Dialog component is the next step.
  • The users page still changes roles with a cycle button rather than a select, because a select would change the API call.
  • Many products share one photo because the seed's image service (loremflickr) returned errors; that is data, not design.
  • The admin "before" capture shows an icon-only sidebar. That is a capture artifact: the layout read the window width before the emulated size applied. The "after" capture forces a resize, and in a real browser the labels show in both versions.
  • Newsletter, social and app-store buttons still have no backend.

Run it

Fix MONGODB_URI in .env.local first: URL-encode special characters in the password (@ → %40). Then:

npm install
npm run dev            # http://localhost:3000
npm run promote-admin -- you@example.com   # first admin, then sign out and in

The screenshots came from a separate freshbasket_design_preview database on the same cluster, so your own data was not touched. Drop that database when you no longer need it.
